## Feature-count reconciliation

- **Evolab genome substrate (searchable signals):** exactly **6** features, `src/evolab/registry.py:315-401` (`_default_registry`): `lineup_platoon_share`, `lineup_vs_primary_pitch`, `primary_pitch_share`, `top_minus_bottom`, `starter_velocity_gap`, `starter_groundball_share`. Each is a `SignalRegistry.register()` call with a mechanism, a frozen sign, and a 3-rung ladder. `src/evolab/bitsets.py:36` independently states "6 features x 3 rungs x 2 sides = 36 masks per world" — confirms 6, not 7 or 9.
- **Matrix-computed but unregistered:** `src/research/matrix.py:243-246` computes 9 per-side feature slots (`lineup_platoon_share, starter_platoon_gap, lineup_vs_primary_pitch, primary_pitch, primary_pitch_share, top_minus_bottom, lineup_vs_starter_history, starter_velocity_gap, starter_groundball_share`) — 3 of those 9 (`starter_platoon_gap`, `primary_pitch`, `lineup_vs_starter_history`) are computed into the JSONL cache and displayed on the dashboard but never registered as a searchable genome signal.
- **Legacy detector family (`src/detect/detectors.py`):** **11** `Detector` subclasses (line numbers 86, 223, 280, 368, 420, 514, 561, 623, 702, 767, 842). None of `src/detectors/` or `src/features/` exists (`find . -type d -name detectors` / `-name features` returned nothing under `src/`).
- **`src/engine/analyze.py` via `src/engine/glue.py build_snapshot`:** reads **zero** matrix/detector features by default. `build_snapshot`'s `features` parameter defaults to `None` → `{}` (src/engine/glue.py:226-254, `features=features or {}`). No call site in the repo passes matrix-derived features into it — `grep -n "build_snapshot(" src/**/*.py` shows only two production call sites, both inside `src/engine/glue.py` itself (`build_truncation_sample`, line 329-334), and both are fed by test-supplied `features_t2h`/`features_t` dicts (`tests/test_engine_glue.py:97-131`). `src/engine/adapters/evolab_system.py:57` (`WorldView(... features=dict(snapshot.features) ...)`) forwards whatever `build_snapshot` was given — which today is nothing, live. The 6-feature genome, when driven through the new engine path, therefore proposes off an **empty feature dict** in production; `src/engine/glue.py:378-416`'s `TrivialAlwaysHomeSystem` exists specifically because of this (its own docstring: "a real genome would honestly see empty `features`... making the differential trivially and uninterestingly empty").

## Distance between today's engine input surface and the intended matchup analyzer

The owner's stated target is a matchup-specific analyzer that reasons over starting pitching, bullpen state, offense, lineups, arsenal/batter interaction, park, weather, umpire, rest/travel, injury, handedness, recent form, historical matchups, market movement and book disagreement, all point-in-time safe, feeding one coherent decision path from raw stores through the genome factory into a live brief and into historical replay. What exists is two disconnected systems of very different maturity: a live, human-facing brief (`src/cli.py cmd_brief` → `src/detect/detectors.py`'s 11 detectors → `src/report/dashboard.py`) that covers roughly 10 of the 16 rows above with real PIT-safe stores but zero connection to the evolab genome/factory or to the new `src/engine` waist; and a PIT-hardened, contract-enforced new engine (`src/engine/snapshot.py`, `src/engine/glue.py`, `src/core/asof.py`) that is architecturally correct — price-blind by type, stop-at-T by construction, per-field graded A/D — but is fed by nothing: `build_snapshot`'s `features` argument is empty in every live call because no code path joins `src/research/matrix.py`'s row-per-game feature cache (or any live equivalent of it) to `src/engine/glue.py`, so the 6-feature genome that the factory (`src/evolab/genome.py`, `src/evolab/bitsets.py`) can search over never receives a signal outside of tests and the 2023-24 replay universe. Quantified: of the 16 matchup dimensions the owner named, roughly 10 have real, PIT-safe, live-wired data (starting pitching, offense, lineups, arsenal/batter interaction, weather, home/away, handedness, historical matchups, book disagreement, rest/travel-ish via TravelLoad); 6 registered searchable features exist for the genome to evolve over, against 9 matrix-computed candidates and 11 live detectors — a ratio of roughly 1 wired-and-searchable feature for every 2 detectors/candidates that already exist in some form; and the new `src/engine/analyze.py` path, despite being the intended long-term seam, reads 0 of those features live today, running instead on a documented placeholder (`TrivialAlwaysHomeSystem`) whose entire purpose is to keep the pipeline exercising real price data while honestly admitting it has no real matchup signal behind it.
