# API Contracts

**This is the interface the design system consumes.** Every shape below is
pinned by `tests/test_api_contracts.py`, which asserts REQUIRED KEYS and
TYPES against real responses (built from offline fixture data), never an
exact-match on the full key set. That means:

- A key listed here will always be present, with the stated type.
- A payload may carry EXTRA keys beyond what's listed (a `freshness` block,
  an `odds_meta` addition, a new field) — those are additive and safe to
  ignore until this doc adds a row for them.
- If a design or client needs a field that isn't listed here yet, ask for
  it to be added to the contract test first — an untested field can change
  shape without warning.

Generated by hand from the same fixtures the contract tests use
(`tests/test_api_contracts.py`); when that test file changes, update this
doc alongside it.

## Vocabulary rules (apply across every table below)

| Rule | What it means |
|---|---|
| Timestamp | Any field ending in `_utc`, or named `generated_at`, is an ISO-8601 string with an explicit UTC offset (`...+00:00` or `...Z`). Never assume a timezone. |
| American price | `american_price`, `away_price`, `home_price`, `best_price` are plain integers (e.g. `-125`, `140`) — never a float, never a numeric string. |
| Probability vs. percentage | Fields named `*_fair`, `*_probability`, `implied_probability` (e.g. `market_implied_consensus.away_fair`) are **fractions in [0, 1]** — this is the de-vigged market-implied consensus vocabulary, not a percentage. A field whose name contains `pct`/`percent` (e.g. `improvement_return_pct`) is a **float in [0, 100]** and is always paired with a `label` field describing what it means. Do not conflate the two. |
| No win probability | No payload anywhere in this API emits a model win-probability field (`win_probability`, `win_prob`, `p_win`, `true_probability`, ...). The betting model is uncalibrated; this is a permanent product rule, not a gap to fill in later. |
| No HTML | No string value in any payload contains an HTML tag. Render text fields directly; nothing needs sanitising. |
| `recommendation` | Wherever it appears (`POST /betcheck`), this field is **permanently `null`**. Ranker Engine 2 (bet recommendations) is gated off; this is a field stating "we do not do that," not an omission. |

## `POST /betcheck`

Checks one stated bet against the real domain path for its game
(`api/betcheck.py`, `src/analysis/betcheck`, `src/analysis/contracts.BetCheckContract`).

Request body:

| Field | Type | Notes |
|---|---|---|
| `date` | string | |
| `away` / `home` | string | club abbreviations |
| `side` | string | `"away"` \| `"home"` only — team-name resolution is the client's job |
| `american_price` | integer | rejected (422) outside a plausible magnitude (roughly 100–100000) |

Response:

| Field | Type | Notes |
|---|---|---|
| `query.raw` | string | |
| `query.parsed` | boolean | |
| `game` | object \| null | `{away, home, date, game_id, start_time_utc, venue, ...}` when the game was matched |
| `thesis_support` | array | list of `Claim` objects |
| `counterargument` | array | may be empty |
| `counterargument_lines` | array of strings, never empty | renders `"No significant counterarguments found"` when `counterargument` is empty — structurally guaranteed, never a blank section |
| `best_available_price` | object \| null | `QuotedPrice`: `{book, american_price, observed_utc}` |
| `market_consensus` | object \| null | `MarketImpliedConsensus`: `{implied_probability, books, observed_utc}` — a fraction in [0, 1], distinct from `best_available_price` |
| `price_improvement` | object \| null | line-shopping value only — never EV, never an edge |
| `your_price_below_market` | boolean \| null | |
| `what_changed` | array | |
| `recommendation` | null, always | Ranker Engine 2 gate — see vocabulary rules above |
| `strongest_reason` / `weakest_reason` / `historical_support` / `evidence_status` / `bottom_line` | string \| null | |

Unknown game: structured `404`. Implausible price: `422` (pydantic
validation), not a `500`.

## `GET /my-bets`, `POST /my-bets`, `DELETE /my-bets/{bet_id}`

The authed user's saved bets (`api/mybets.py`, `src/appstate/savedbets`).
Every request is scoped to the authenticated user — one user can never
read or delete another's rows, even by guessing an id.

`GET /my-bets` and the object `POST /my-bets` returns:

| Field | Type | Notes |
|---|---|---|
| `bets` | array of bet objects | (`GET` only; `POST` returns one bet object directly) |
| `id` | integer | |
| `game` | string | |
| `side` | string | |
| `price` | number \| null | |
| `saved_at` | string (ISO-8601 UTC) | |
| `snapshot_digest` | string \| null | fingerprint of the evidence shown at save time; opaque to this endpoint |

`DELETE /my-bets/{bet_id}` returns `{"deleted": true, "id": <int>}` or a
structured `404` if the bet doesn't exist or belongs to another user.

## What's intentionally NOT in this API

- No bet-placement endpoint of any kind, ever. Nothing here confirms a
  wager, holds a stake, or returns a `wager_id`.
- No model win-probability field, on any endpoint (see vocabulary rules).
- No `recommendation` value other than `null` (Ranker Engine 2 is gated).
