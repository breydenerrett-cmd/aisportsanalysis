# SR1 — home underdog price band: not run

**Verdict: NOT EVALUATED. No row of outcome data was read.** This is not a
null and not a fail. SR1 was never pre-registered, only drafted, and this
lane's own standing rule (stated in its source document three separate
times) forbids reading a single row against results until a frozen spec
file with a hash exists and has had Fable-tier review. Neither has happened.
Running the analysis anyway would have been the exact violation the lane
was designed to prevent, so it was not run.

This document exists to record that finding precisely, the way this project
records a BLOCKED entry: what was checked, what is missing, and what has to
happen before a verdict can be drawn.

## 1. What was asked

The owner said underdogs in the +100 to +250 range often carry real value.
`docs/RESEARCH_STRATEGY_REPLICATION.md` proposes a matching candidate, SR1,
ranked first in that lane's shortlist and listed in its summary table as
`READY_UNTESTED (top-ranked, drafted in full)`. The request was to run SR1
as pre-registered and report the result.

## 2. SR1's draft rule, quoted verbatim

From `docs/RESEARCH_STRATEGY_REPLICATION.md`, Template A ("SR1/SR2: Home
underdog price-band effect"):

> **Rationale.** Favorite-longshot bias (bettors overpay for favorites,
> underpay for dogs) is a well-documented market phenomenon in horse racing
> and sports betting broadly, and V2's M5 (N12) already measured that de-vig
> methods diverge specifically on lopsided prices in our own data ... What
> has never been tested is whether that divergence, combined with home field
> advantage, is large enough and one-directional enough to be profitable at
> a specific price band, as forum "system" sites claim.
>
> **Exact feature/rule.** Home team is priced as an underdog (American odds
> between +100 and +150 inclusive, at the recommendation-time consensus
> price) → back the home team, moneyline. Sub-hypothesis (nested, not a
> separate family member): the same rule restricted to divisional matchups.
>
> **Direction.** Back the home underdog. Fixed by the source before any
> read.
>
> **Market.** MLB moneyline (h2h), full game.
>
> **Sample gate.** Minimum 30 qualifying selections per season per
> sub-hypothesis (consistent with N8's floor rule) ...
>
> **Effect floor.** +1pp over de-vigged consensus implied probability
> (standing floor), date-clustered 95% CI must exclude zero.
>
> **Replication criterion.** 2023 screen, 2024 replication; both years must
> agree in sign; BH-FDR q=0.10 applied over this family jointly with
> Template B (and Template C if drafted).
>
> **Falsification criteria (battery, RULES_VERSION 2.0.0).** Team
> concentration, book concentration, season-split stability, dose-response
> (marked not applicable, flat band, no gradient claimed), extreme-date
> removal.
>
> **Pre-registered prior, stated now.** MEDIUM-LOW ... Recorded before any
> look, per the M3 precedent of stating priors early so a positive gets
> extra scrutiny.

Note the declared price band is **+100 to +150**, not the owner's spoken
"+100 to +250." The owner's instinct and SR1's drafted rule are related but
not identical; that distinction matters if this is ever registered, since
the band cannot be widened after the fact to match the owner's framing
without triggering the "no rescue by threshold or definition change" rule
(T8) this project treats as absolute.

## 3. Why this was not run: the registration gap

`docs/RESEARCH_STRATEGY_REPLICATION.md` is explicit, in its own words, three
times over, that nothing in it is a pre-registration:

- Line 3-6: **"Status: DESIGN DOCUMENT ONLY. Nothing registered, nothing
  evaluated, no data read for outcomes. This document proposes a lane; it
  does not open one. Pre-registration of any shortlisted family still
  requires its own document and Fable review before a single row is read
  against results, per standing rule."**
- Section 4 header: **"These are templates only. No family file exists, no
  hash is frozen, and no row has been read against outcomes. Registration
  requires a separate act (a frozen spec file, as V4/V5 did) plus Fable
  review before any evaluation begins."**
- Closing line: **"Nothing above is registered. The next step, if Brey
  approves, is a separate pre-registration act (frozen spec file + hash,
  following the V4/V5 pattern) for Template A and Template B jointly as one
  family, then Fable review of that registration before any 2023 screen is
  run."**

`READY_UNTESTED` in the summary table means "drafted and ranked, ready to be
promoted to a real registration" — not "pre-registered and awaiting
execution." Checked independently, not just taken from the document's own
claim:

- `data/research/alpha_registry.jsonl` (the append-only ledger of every
  registered hypothesis, sweep and audit this project has ever spent) has
  88 rows. None reference SR1, SR2, `home_underdog`, or
  `strategy_replication`.
- A repository-wide search for any file named `SR1*` (a frozen spec file
  would need one, following the V4/V5 pattern this document cites) found
  nothing.
- `docs/RESEARCH_CATALOGUE.md`, the master list of every family this project
  has actually registered or resolved, does not mention SR1 or SR2 anywhere.
- `docs/ARCHITECTURE_BETTING_ENGINE.md` section 5, Gate G5 ("Ceiling"):
  "A **pre-registered** cell clears its ceiling with placebo worlds run
  through the full argmax..." — the gate presupposes registration has
  already happened before a cell is evaluated at all.

All four checks agree: SR1 has a drafted rule, a stated rationale, and a
ranked position, but no frozen spec, no hash, no Fable-tier review, and no
registry entry. It is not pre-registered. Evaluating it now — even
faithfully, even changing nothing — would itself be the violation this
lane's own standing rule exists to prevent, and would put a number into the
world for a "test" whose exact rule was never frozen against outside review
before anyone looked at outcomes.

## 4. Data check (performed, not acted on)

Checked for completeness, since the pre-registration gap was the actual
blocker rather than data availability:

- SR1's declared data need is odds history only. The document names
  `data/historical/odds_history/mlb_2023.jsonl` and `mlb_2024.jsonl`; those
  exact paths do not exist. The corresponding data is archived and
  compressed at `data/archive/historical/odds_history/mlb_2023.jsonl.gz`
  (2,931,333 bytes compressed, 57,390,275 bytes uncompressed) and
  `mlb_2024.jsonl.gz` (2,199,377 bytes compressed, 41,336,660 bytes
  uncompressed), per `gzip -l`. Row counts were not read out of the
  decompressed content — doing so would be reading data toward an
  unregistered test, which is exactly what is being declined here.
- 2025 odds data is also archived (`mlb_2025.jsonl.gz`) and is tuning-only
  per standing rule; not eligible as a replication or confirmation window
  even once SR1 is properly registered.
- 2026 data exists under `data/raw/oddsapi/2026`. Per standing rule,
  2026-01-01 through 2026-08-27 is sealed and untouched, one look ever,
  after Stage 5 freeze and Brey's go; 2026-08-28 onward is forward proof.
  Neither range was opened for this check; the registration gap made it
  moot.

No file under `data/` was parsed for content in the course of this check.
Only directory listings, file sizes, and gzip metadata were read.

## 5. What this does and does not license

- Does not confirm the favorite-longshot / home-underdog mechanism is
  profitable at any price band on this project's data.
- Does not refute it either. There is no result, positive or negative, to
  report on the strategy itself.
- Does not license widening, narrowing, or otherwise adjusting SR1's band
  (or any other term) to better match the owner's spoken "+100 to +250" —
  that would be a definitional change made before a first look, which is
  allowed, but it has to happen in a frozen spec file under Fable-tier
  review, not informally in this doc or in chat.
- Licenses exactly one next step: if this test is wanted, someone at
  Fable-tier needs to take Template A (optionally jointly with Template B,
  as the source document recommends for FDR power), freeze it into a spec
  file with a hash, and review that registration — after which a 2023
  screen may be run for the first time, followed by 2024 replication, the
  falsification battery, and only then a verdict.
