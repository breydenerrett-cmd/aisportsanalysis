## Rules every post follows

- Paper bets only; the record is public and shows losses. No claim of any result. No promise a hound will do anything.
- A hound's pre-game post is a paper bet in character, not advice. Only hounds with a price **better than -200** get a post; if a hound's price is -200 or worse, skip it that day.
- Fill the `[ ]` fields from the live record at https://linehound.app/web/#/hounds the same day. Numbers are never invented and never quoted from yesterday. If a field has no real value, do not post that item.
- Every recap shows the bet count beside the record. A small count is said out loud ("11 bets, tiny sample").
- Responsible-gambling line on every Post C and at least weekly elsewhere: `21+. Paper bets, not advice. Bet at your own risk. 1-800-GAMBLER.` (**[RG]** below).
- Never reference Bet Check. No sportsbook or casino links. Disclose the account is run by the builder.
- Link posts use `?utm_source=x&utm_medium=organic&utm_campaign=x_1029_dayNN`. X penalises links in the first post of a thread: put the link in a reply or the last post where noted. X posts must stay at 280 characters; the auto-poster test (below) enforces it.
- Cull posts ("Take them out back") are posted only when a real cull happened (`feeds/kennel.rss` shows it). Slots marked **CULL** have an evergreen fallback if none happened.

## Three posts a day

- **A, morning (about 9:30 AM PT, after the 9 AM lineup):** hound trash talk before games. Fields from today's slate.
- **B, afternoon (about 1 PM PT):** rotates: build-a-hound-in-one-sentence demo, culls/headstones, or a hound-vs-hound challenge.
- **C, night (about 9 PM PT):** public record recap, losses included.

The fields: `[HOUND]` hound name, `[GAME]` the matchup, `[SIDE]` the side it took, `[PRICE]` the price (better than -200), `[W-L]` and `[N]` record and bet count, `[BIGGEST_LOSS]` its worst bet with the reason from its record page.

### What the owner must do (the owner's own hands: account, card, secrets)

1. Sign in to the X account that will post and open https://developer.x.com/en/portal/dashboard . Create a developer app (Project then App). Accept the developer terms yourself.
2. In the app's settings set "User authentication settings": App permissions **Read and write**, type **Web App / Automated App or Bot**, any https callback (https://linehound.app is fine).
3. In the app's Keys and tokens page generate: API Key, API Key Secret, Access Token, Access Token Secret (OAuth 1.0a user context for the posting account) and note the Bearer token if shown. Copy them once; they are not shown again.
4. Add a small prepaid balance if the console asks for one (pay-per-usage). Amount is the owner's call.
5. Set them as secrets by name only, never in a file or chat: `fly secrets set X_API_KEY=... X_API_SECRET=... X_ACCESS_TOKEN=... X_ACCESS_SECRET=... -a linehound-prod` and the same four as GitHub repository secrets with the same names. Add `X_POSTING=off` as the default switch.
6. Tell Claude "x keys in". Claude does not read or print the values.

### What we would build (not built; needs the owner's keys and a go)

An auto-poster that reads the server's existing post feeds, so it is the same pattern the Zaps already use (`docs/ZAPS.md`): the server writes text, something else delivers it.

- **Queue:** a table `x_post_queue` (id, kind in {trash_talk, recap, build_demo, cull}, text, source_event_guid UNIQUE, scheduled_for, status in {pending, approved, posted, failed, skipped}, posted_id, created_at). The `source_event_guid` follows the kennel-feed convention (stable per event) so a re-run cannot double-post.
- **Writers (code, not a model):** `src/hounds/x_posts.py` builds each text from the same data the digest and kennel feed read (`src/hounds/digest.py`, `src/hounds/kennel_feed.py`), using the templates above. Every number comes from the ledger. A post is dropped, not guessed, if a field is missing.
- **Gate (a hard test, same style as `tests/test_customer_language.py`):** every queued text must be 280 characters or fewer, contain no word on the project's banned-word list, carry a responsible-gambling line on recaps, show a bet count next to any record, and never include a price at -200 or worse.
- **Publisher:** `POST https://api.x.com/2/tweets` with OAuth 1.0a, run from the existing hourly scheduler. Default `X_POSTING=off`; step 1 is "approve mode" where posts show on an owner admin page and nothing is sent until the owner presses Approve. Auto mode only after a week of clean approvals.
- **Feed for Zapier (optional, zero API cost):** `/feeds/x-queue.rss` so the existing Zapier route can post to X through Zapier's own X integration instead of the API if the owner prefers; the existing Zaps already deliver the daily digest and kennel news to Discord this way, and the same item guids stop duplicates. Caveat: that path costs Zapier tasks (1 per post, about 42 over the two weeks).
- **Kill switch and audit:** `X_POSTING=off` stops everything; every send is logged with the returned post id; failures alert through the existing `feeds/alerts.rss`.

Build size: about one day for the queue, writers and gate; the API call itself is a few lines. Recommendation for 10-31: do not wait for the build. Post the first days by hand from this file; build the queue after the keys exist.
