# Go live: what only the owner can do (rewritten 2026-10-01 21:50Z)

Production is deployed and serving at `https://linehound-prod.fly.dev`.
Billing is OFF there (no secrets are set on `linehound-prod` at all). Nothing
below has been done by anyone else, and none of it can be done from the
repository. In order:

## 0. Before any outreach is sent: make signups visible (2 minutes)

**DONE 2026-10-02 04:16Z.** `APP_ADMIN_TOKEN` is deployed; `/admin/*` answers 401 without the token (it was 404). The admin page is `https://linehound.app/web/admin.html`. The steps are kept below for a rotation.

Production has no admin token, so `/admin/*` answers 404 and nobody can see
who signed up or which outreach link they came from. Visits and signups are
recorded anyway (on the production volume; they survive every redeploy), but
nothing can read them. This does not need Stripe or the domain.

Run these in PowerShell (the terminal in the Claude app, or Windows
Terminal). Do them back to back: step B reads the clipboard that step A
filled, so copy nothing in between.

**A. Make a token and put it on the clipboard** (prints one line, never the
token):

```bash
python -c "import secrets,subprocess; subprocess.run('clip', input=secrets.token_urlsafe(32), text=True, check=True); print('A new token is on your clipboard.')"
```

**B. Set it on production** (the value goes from the clipboard to Fly; it is
not typed, shown or kept in the shell history):

```bash
fly secrets set -a linehound-prod "APP_ADMIN_TOKEN=$(Get-Clipboard)"
```

Expected: a few lines about updating the machine, ending without an error.
It never prints the value. Production restarts once (about a minute; the
first page loads after that are slow for a minute or two).

**C. Paste the token into your password manager now**, while it is still on
the clipboard. Name it "LineHound admin token (production)".

**D. Check it, without showing anything secret:**

```bash
fly secrets list -a linehound-prod
```

Expected: one row, `APP_ADMIN_TOKEN`, with a digest (a short hash, not the
value) and status `Deployed`.

Then open `https://linehound-prod.fly.dev/web/admin.html`, paste the token
into the box, and the overview, the funnel (visits and signups by source)
and the user list appear. Section 3 below sets Stripe's values; it no longer
needs to set this one.

To undo (admin pages go back to 404):

```bash
fly secrets unset -a linehound-prod APP_ADMIN_TOKEN
```

Never paste the token into chat. If it is ever exposed, run A and B again:
the old token stops working at once.

## 1. The domain

**DONE 2026-10-02 04:26Z.** Four records in Cloudflare (A and AAAA for `@` and for `www`, all DNS only). `https://linehound.app` serves the site over TLS 1.3 with a Let's Encrypt certificate; http redirects to https; `/` goes to the landing page; the paid card and the admin routes refuse a visitor with no token. The steps are kept below for reference.

`linehound.app` is on Cloudflare's nameservers but has no A, AAAA or CNAME
record for the apex or for `www`, and `fly certs list -a linehound-prod` is
empty (checked 2026-10-02 02:50Z). So `https://linehound.app` resolves to
nothing. Outreach links, link previews and the Stripe return address all
wait on this.

**A. Ask Fly for the two certificates** (free; each command also prints the
DNS records Fly expects; if they differ from the table below, use what Fly
prints):

```bash
fly certs add linehound.app -a linehound-prod
```

```bash
fly certs add www.linehound.app -a linehound-prod
```

**B. In Cloudflare** (dashboard, linehound.app, DNS, Records, Add record),
add these three. The addresses are this app's own, read from
`fly ips list -a linehound-prod` on 2026-10-02:

| Type | Name | Value | Proxy status | TTL |
|---|---|---|---|---|
| A | `@` | `66.241.125.250` | DNS only (grey cloud) | Auto |
| AAAA | `@` | `2a09:8280:1::1a2:5097:0` | DNS only (grey cloud) | Auto |
| CNAME | `www` | `linehound-prod.fly.dev` | DNS only (grey cloud) | Auto |

Proxy must be OFF (grey cloud). With the orange cloud on, Fly cannot prove
it owns the name and the certificate never issues.

**C. Check** (repeat after a few minutes until both say Ready):

```bash
fly certs list -a linehound-prod
```

Expected: `linehound.app` and `www.linehound.app`, each with status `Ready`
(first `Awaiting configuration`, then `Awaiting certificates`, then `Ready`;
usually under ten minutes once the records exist).

To undo: delete the three records in Cloudflare and run
`fly certs remove linehound.app -a linehound-prod` (and the same for `www`).
Nothing on `linehound-prod.fly.dev` changes either way.

After both are Ready, tell Claude: the canonical address, link previews,
outreach links and the checks on the real domain (landing, signup, record,
postseason, protected routes, www redirect) are done from there.

## 3. Turn billing on in production (one command, all values at once)

Setting these one at a time restarts the machine between each and leaves
billing half-configured in between. The site stays up either way (`/health`
reports `checkout: broken` and the pages say checkout is not open), but do
it in one command:

```bash
fly secrets set -a linehound-prod APP_ADMIN_TOKEN=<long random> BILLING_PROVIDER=stripe STRIPE_API_KEY=<secret key> STRIPE_WEBHOOK_SECRET=<signing secret> STRIPE_BETA_PRICE_ID=<price id> STRIPE_TRIAL_DAYS=7
```

Then open `https://linehound.app/health`. The `checkout` block must read
`"status": "ok"` and `"mode": "live"` (or `"test"` if you used test keys
first, which is the safer first run). If it reads `broken`, the `reason`
names the variable that is missing.

## 6. Support

There is no email sender. A subscriber who loses the access token can only
get back in if you re-issue one:

```bash
curl -X POST https://linehound.app/admin/users/token -H "X-Admin-Token: <APP_ADMIN_TOKEN>" -H "Content-Type: application/json" -d "{\"email\": \"their@email\"}"
```

Send the token it returns over the channel they wrote from. Every older
token for that account stops working.

With checkout off the buttons say "Get notified when checkout opens".
Nothing sends that notice. The saved emails are on the admin page's user
list (step 0) with status `waitlisted`; write to them yourself when checkout
opens.
